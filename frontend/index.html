What is a Design Pattern?

Software Engineering & Architectural Foundation
Overview
💡 Meaning & Definition:

A Design Pattern is a formalized, reusable architectural template and proven best-practice solution to commonly occurring software engineering problems. Rather than writing ad-hoc, tightly coupled code, design patterns introduce clean object-oriented structures (separation of concerns, loose coupling, single responsibility, open-closed principle) that make enterprise applications robust, modular, testable, and easily extensible.

🎯 How it is Implemented in TiMN (Features):

TiMN is built from the ground up using 8 classic Gang of Four (GoF) design patterns across all 3 software design categories: Creational (Singleton, Factory Method), Structural (Protection Proxy), and Behavioral (Observer, Chain of Responsibility, Strategy, Template Method, Memento). Every core interaction—from dynamic movie recommendation filters and user watchlist undo states to role-based access security and report exports—is backed by a concrete design pattern.

!

1. Singleton Pattern

Creational
💡 What it means:

Ensures that a class has only one single global instance throughout the entire lifetime of the application, and provides a centralized global access point to it. This guarantees shared state consistency and prevents duplicate resource allocations.

🎯 Where it is Implemented (Features in TiMN):

MovieDatabase.java & api/index.js: Central in-memory repository managing all 41 movies, user accounts, watchlists, and active observers. All HTTP API requests across users query and synchronize with this single shared database instance.

MovieDatabase.java
!

2. Factory Method

Creational
💡 What it means:

Defines an interface for creating objects, but encapsulates the concrete instantiation logic inside a dedicated factory method. This decouples object creation from business logic, making adding new movie types seamless without modifying existing client code.

🎯 Where it is Implemented (Features in TiMN):

MovieFactory.java: Encapsulates movie object instantiation from both persistent flat files (createMovieFromFile) and admin creation requests (createMovie), safely parsing genres, IMDb ratings, and streaming platform metadata.

MovieFactory.java
!

3. Observer Pattern

Behavioral
💡 What it means:

Defines a one-to-many publish-subscribe communication dependency. When a subject (publisher) changes state or publishes a message, all registered observers (subscribers) are automatically notified and updated in real-time without tight coupling.

🎯 Where it is Implemented (Features in TiMN):

NotificationService.java & UserObserver.java: Whenever an admin uploads a new title, deletes content, or sends a platform announcement broadcast, all active user observers automatically receive live push alerts inside the notification bell feed.

NotificationService.java
!

4. Protection Proxy

Structural
💡 What it means:

Acts as an intermediary security guard that controls access to a sensitive service. It intercepts client requests, verifies identity and authorization credentials, and blocks unauthorized actions before delegating legitimate requests to the real underlying service.

🎯 Where it is Implemented (Features in TiMN):

MovieServiceProxy.java: Enforces role-based security. Only users authenticated with the ADMIN role (e.g. admin@gmail.com) are allowed to add or delete movies. Regular user accounts are intercepted and blocked with HTTP 403 Forbidden.

MovieServiceProxy.java
!

5. Chain of Responsibility

Behavioral
💡 What it means:

Decouples request senders from processing receivers by passing data sequentially through an ordered chain of independent filtering handlers. Each handler performs its specific check and passes the filtered candidate list to the next handler in line.

🎯 Where it is Implemented (Features in TiMN):

RecommendationChain.java: Powers movie recommendations by executing an extensible 4-stage pipeline: GenreHandler ➔ LanguageHandler ➔ RatingHandler ➔ PlatformHandler. Each handler isolates filtering criteria cleanly.

RecommendationChain.java
!

6. Strategy Pattern

Behavioral
💡 What it means:

Encapsulates a family of algorithms into separate, interchangeable strategy classes and makes them swappable at runtime. The client context delegates execution to the chosen strategy without needing messy if-else or switch logic.

🎯 Where it is Implemented (Features in TiMN):

SortingStrategy.java & CatalogSorterContext.java: Enables real-time catalog sorting. Users dynamically switch between RatingSortStrategy, YearSortStrategy, TitleSortStrategy, and PopularitySortStrategy on the Movies page.

SortingStrategy.java
!

7. Template Method

Behavioral
💡 What it means:

Defines the skeleton of an algorithm in an abstract base class template, deferring concrete rendering and formatting steps to specialized subclasses without altering the invariant structure and sequence of execution.

🎯 Where it is Implemented (Features in TiMN):

WatchlistReportTemplate.java: Outlines the standard 3-phase algorithm (Header ➔ Movie Rows ➔ Summary Footer) for exporting user watchlists into diverse formats: JsonWatchlistReport, MarkdownWatchlistReport, HtmlWatchlistReport, and PlainTextWatchlistReport.

WatchlistReportTemplate.java
!

8. Memento Pattern

Behavioral
💡 What it means:

Captures and externalizes an object's internal state into an immutable memento snapshot without violating encapsulation rules. The object can be restored to this exact previous state at any time, implementing clean Undo and Rollback capabilities.

🎯 Where it is Implemented (Features in TiMN):

WatchlistMemento.java & WatchlistCaretaker.java: Whenever a movie is added or removed from a user's watchlist, a snapshot memento is saved to the caretaker stack. Clicking "Undo (Memento)" instantly restores the previous watchlist state.

WatchlistMemento.java

8 Gang of Four Design Patterns Implementation
1. Singleton Pattern
MovieDatabase.java
Guarantees a single in-memory database instance managing all loaded movies and preventing duplicate state across threads.

WatchlistMemento.java
Captures and restores user watchlist snapshots, allowing seamless Undo operations without violating encapsulation.
